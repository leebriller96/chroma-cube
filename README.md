# Chroma Cube

정면 직교 카메라로 보는 2D 횡스크롤 퍼즐. 카메라 각도가 0 이라 화면은 완전한 2D 고,
시점을 90° 돌리는 그 순간에만 카메라가 들리면서 세계가 3D 라는 게 드러난다. (Fez 의 그 규칙)

## 규칙

- `←` `→` : 화면 기준 좌우로 한 칸 구른다
- `A` `D` : 시점을 90° 돌린다 (`Q` `E` 도 같다)
- `R` : 스테이지 처음부터
- 터치: 가로로 끌면 시점이 손가락을 살짝 늦게 따라 돈다. 한 번에 한 칸까지만 돌고, 90°의 40% 를 넘겨야 넘어간다. 톡 누르면 그쪽으로 한 칸 걷는다
- 큐브와 색이 같은 칸만 밟힌다. 색이 다르면 넘어가려다 **띵!** 하고 튕겨 돌아온다 (손해 없음)
- 발판 옆면에 빛나는 버튼이 박혀 있으면 스위치다. 색과 상관없이 밟히고, 밟으면 큐브가 그 색이 된다
- 윤곽만 반투명하게 떠 있는 칸은 그림자 칸. 같은 세로줄 뒤에 있는 것의 색을 그대로 비춘다
- 문에는 봉인 고리가 반씩 새겨진 문짝 두 짝이 닫혀 있다. **고리가 하나로 이어질 때**만 봉인이 금빛으로 켜지고 문짝이 젖혀진다
- 고리를 잇는 방법은 둘이다 — 흩어진 조각을 한 줄로 겹치거나(시점을 돌려서), 두 몸이 반쪽씩 이고 다니다 한 칸에 포개거나
- 열린 문 안으로 큐브가 천천히 줄어들며 빨려 들어가면 클리어
- 판이 크면 큐브에 바짝 붙어 시작했다가 카메라가 쭉 물러나며 전체를 드러낸다 (바람 소리와 함께)
- 한 칸 위나 아래도 갈 수 있다. 계단을 오를 때는 층계참 모서리를 축으로 **반 바퀴 굴러** 넘어간다

### 깊이가 접힌다

화면이 2D 라서 **깊이가 다른 칸들이 같은 세로줄에 겹쳐 보인다.**
한 칸 옆으로 걸으면 그 세로줄에서 **카메라에 가장 가까운 칸**으로 간다.
카메라가 완전한 정면이라 뒤 겹은 앞 겹에 **한 픽셀도 안 보이게** 가려진다 —
스위치 버튼도 발판 표면에 붙어 있어서 튀어나오지 않는다.
앞 칸의 색이 안 맞으면 뒤에 맞는 칸이 있어도 튕긴다 — 시점을 돌려
그 칸을 앞으로 끌어내야 밟을 수 있다. 이게 이 게임의 전부다.

정면(view 0, 2)에서는 가로로 이동하고, 90° 돌린 시점(view 1, 3)에서는
겹과 겹 사이를 오간다. 180° 돌리면 뒷줄이 앞줄이 되어 반대로 걷는다.

이 규칙에서 나오는 두 가지 퍼즐:

- **숨기기** — 앞 겹이 뒤 겹을 완전히 가린다. 색이 안 맞는 발판 뒤에 맞는 발판이 숨어 있다.
- **착시로 잇기** — 정면에서 멀찍이 떨어져 보이던 두 땅도, 깊이가 한 겹 차이라면
  90° 돌리는 순간 바로 옆 칸이 된다. 끊긴 길을 그렇게 건넌다.

## 보이는 것

Monument Valley 쪽이다. **광원이 하나도 없다.** 조명 계산 대신 면마다 칠할 색을 직접 정한다.

- 발판 옆면의 명암은 [`textures.ts`](src/render/textures.ts) 가 캔버스에 띠로 그려 굽는다.
  위쪽 빛 받은 띠 · 몸통 · 아랫단 그림자. 조명이 없어도 두께가 읽히고, 색이 절대 탁해지지 않는다
- 발판은 칸 높이를 거의 다 채운다(0.88). 그래야 층을 쌓았을 때 계단이 통짜 돌계단으로 붙어 보인다.
  남는 0.12 는 돌과 돌 사이 이음매가 된다
- 뒤집힌 세계가 있는 판에서는 그 띠가 **위아래로 반씩 갈린다.** 윗면이 파랑이면 아랫면은 빨강이다 —
  밑에 매달린 큐브가 걷는 길이 겉에서 그대로 보인다
- 문 · 고리 조각은 늘 카메라를 마주 본다. 어느 시점에서 봐도 같은 문으로 읽히도록
- 배경의 먼 탑들도 판과 같은 언어(모난 돌덩이와 아치)로 지어, 배경이 따로 놀지 않게 한다
- 마지막에 [`print.ts`](src/render/print.ts) 가 옅은 비네트와 아주 약한 디더만 얹는다

## 스테이지 쓰는 법

[`src/core/stages.ts`](src/core/stages.ts) 에 글자 지도로 적는다.
**한 줄이 깊이 한 겹**이고, 첫 줄이 카메라에서 가장 가까운 앞 겹이다.

```
'b. b. r. r. r*',   // 앞 겹 (z=0)
'.. r! .. .. ..',   // 한 겹 뒤 (z=-1) — view 0 에서는 앞 겹에 가려 안 보인다
```

| 글자 | 뜻 |
| --- | --- |
| `..` | 빈 공간 |
| `b.` `r.` | 파란 / 빨간 땅 |
| `b!` `r!` | 그 색으로 물들이는 스위치. 옆면에 빛나는 버튼이 박혀 있다 |
| `b*` `r*` | 그 색으로만 들어갈 수 있는 문 |
| `.?` | 그림자 칸. 제 색이 없고, 같은 세로줄의 실체에서 색을 빌린다. 뒤가 비면 아예 없다 |
| `.#` | 고리 조각. 밟을 수 없고, 전부 한 줄로 겹쳐 이어지면 문이 열린다 |
| `.~` | 교대 칸. 색과 무관하게 밟히고, 밟으면 조종권이 발판 반대편 큐브로 넘어간다 |

글자 지도 밖에서 거는 규칙도 있다.

```ts
start: [[0, 2], [1, 2]],       // 시작 [줄, 칸] 또는 [줄, 칸, 높이]. 둘 이상이면 큐브가 여럿이다
startColor: ['red', 'blue'],   // 하나면 다 같은 색, 배열이면 큐브마다 따로
startSide: ['top', 'under'],   // under 면 발판 밑에 거꾸로 매달려 시작한다
```

층을 쌓을 때는 `rows` 대신 `floors` 로 층별 평면도를 적는다. y 가 클수록 위다.

```ts
floors: [
  { y: 0, rows: ['b. b. .. ..'] },
  { y: 1, rows: ['.. .. .. ..',
                 '.. .. b. ..'] },   // 한 겹 뒤, 한 층 위
],
```

이동은 **같은 높이 → 한 칸 위 → 한 칸 아래** 순으로 목적지를 찾는다.
그래서 같은 x 에 높이만 다르게 쌓아 두면 정면에서는 못 오르는 **벽**이고,
90° 돌려 그 블록들이 서로 다른 세로줄로 흩어지는 순간 **계단**이 된다. (「계단」·「두 탑」)

큐브가 여럿이면 **한 칸에 포개져야 문이 열린다.** 막힌 큐브만 제자리에서 튕기므로,
앞선 쪽을 벽이나 잠긴 문 앞에 세워 두고 뒤진 쪽이 따라붙게 만드는 것이 퍼즐이 된다.
색이 다른 둘은 **스위치 위에서만** 포개질 수 있다 — 보통 칸은 색이 하나라 한쪽이 튕기니까.

**뒤집으면 색도 뒤집힌다.** 발판 밑에 매달린 큐브에게 파란 칸은 빨갛게 보인다.
그래서 위아래는 서로 반대색 길이 되고, 같은 문을 쓰려면 두 몸의 색이 서로 달라야 한다.
교대 칸이 하나라도 있는 판에서는 **한 번에 한 큐브만** 움직인다.

새 스테이지를 넣으면 테스트가 BFS 로 최단 수를 재서, 클리어 가능한지와
실수로 서너 수 만에 끝나는 판이 아닌지 검사한다.

### 스테이지를 만들 때 걸리는 함정

90° 돌린 시점(view 1, 3)에서는 겹 하나가 세로줄 하나로 통째로 접힌다.
그래서 그 겹으로 한 발 내디디면 **그 겹에서 카메라에 가장 가까운 칸**, 곧
x 가 가장 크거나(view 1) 가장 작은(view 3) 칸에 내려앉는다. 판 반대편까지 한 수로 건너뛴다.

- 문이나 꼭 필요한 스위치를 겹의 양 끝에 두지 말 것. 두면 한 수에 낚아채인다
- **고리 조각도 같은 함정에 걸린다.** 조각을 한 겹에 몰아 두면 90° 돌리는 순간 저절로 겹쳐서,
  문이 늘 열려 있는 판이 된다. 조각은 x 로 세우고 길은 z 로 내야 잠금이 뜻을 갖는다
- 양 끝은 지금 색으로 밟을 수 없는 칸으로 막아 두면 좋다
- 꼭 필요한 칸은 겹의 **가운데**에 두면, 그 겹에 올라선 뒤 180° 돌려
  그 겹을 앞줄로 만들고 걸어가야 한다 — 이게 긴 판을 만드는 방법이다

## 구조

```
src/core/     three.js 를 모르는 순수 게임 로직 (테스트 대상)
  types.ts      색 · 칸 · 시점의 정의
  view.ts       네 방향 시점 ↔ 월드 좌표 변환. 방향 계산은 전부 여기에만 있다
  stage.ts      글자 지도를 타일로 굽는 파서
  stages.ts     스테이지 데이터
  game.ts       targetSolid() 이 깊이 접힘을 푼다. 이 게임의 심장
src/render/   three.js 표현
  world.ts      씬 · 직교 카메라(각도 0) · 회전할 때만 들어올리는 카메라 · 넓은 판 줌아웃
  backdrop.ts   해와 먼 탑들. 시점을 돌리면 층마다 다른 속도로 흐르고, 주기적이라 끊기지 않는다
  bond.ts       두 몸이 반쪽씩 이고 다니는 고리. 포개지면 하나로 이어진다
  gust.ts       카메라가 물러날 때 스쳐 가는 바람
  textures.ts   하늘 그라데이션과 발판 옆면의 명암 띠. 이미지 파일 없이 캔버스로 굽는다
  metrics.ts    발판 두께처럼 발판과 큐브가 서로 맞춰야 하는 치수
  board.ts      발판 · 스위치 버튼 · 교대 칸 화살표 · 아치 문 · 이어지는 고리 조각
  cube.ts       모서리로 구르는 이동(계단은 반 바퀴), 튕기는 각도 곡선, 문으로 빨려 드는 마무리
src/ui/
  audio.ts      효과음. 오디오 파일 없이 WebAudio 로 합성한다
  hud.ts        스테이지 정보 · 배너 · 터치 버튼
```
